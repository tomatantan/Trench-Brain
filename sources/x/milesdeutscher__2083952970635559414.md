I recently came up with a 6-step framework for designing perfect loops in Claude Code.

If you want to use /loop as efficiently as possible, I highly recommend you follow this loop structure.

This is how you automate anything with loop engineering in Claude:

1. The Trigger

This is what starts the loop without you clicking anything.

This could be a timer ("every morning at 8 am"), or it just fires immediately when you type the command.

2. The Doer

This is Claude actually doing the work.

Reading, writing, researching, coding, whatever the task is.

3. The Checker

Decides whether the work is actually good enough or finished.

Without this, Claude has no way to know if it did a good job; it just assumes it's done and stops.

A good checker asks: does this pass a test? Does this match what I asked for? Is the number correct?

4. Stop Rules

Every loop needs to know when to stop, on success and on failure.

Success stopping: "all tasks are complete."

Failure stopping: "if this fails 5 times in a row, stop and tell me."

Without this, a loop either runs forever or fails the same way repeatedly without ever telling you.

5. Memory

A simple file where the loop writes down what it did and what it learned.

Next run, it reads this first so it doesn't repeat mistakes or forget what it already figured out.

6. Instructions

Lastly, these are the rules the loop should always follow.

Think: your preferences, your constraints, how you like things done.

Read every single time the loop runs, so it always "remembers" who you are.

Put together, a loop is just this:

Something starts it (trigger) → Claude does the work (doer) → something checks if it's actually right (checker) → it stops or tries again (stop rules) → it writes down what happened (memory) → it always follows your rules (instructions)

Master these 6 parts, and you can build a loop to automate anything.
