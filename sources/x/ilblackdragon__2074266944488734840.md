Great to see this passing. 

This is removing something that doesn't work to keep NAER Protocol simpler and cleaner going forward.

Initially I designed developer gas rebate as an incentive for developers to build components that others will reuse.

But as adoption of NEAR evolved - we saw that most applications usually just sponsor gas and take the fees in other ways (spread, subscription, even ads). If smart contract has valuable state - it can charge for it, and if it doesn't - it's just a library and gets bundled into application contract. Especially now when AI can just write any code easily.

Implementation also led to create hard accounting challenge - it's really hard to distinguish this rebate from other user deposits of funds.

It's not really about massively changing the value capture but to simplify the protocol here and avoid developers in the future misusing it.

It's also a great test of House of Stake changing core economics parameters in preparation for other proposals.

Excited to have explicit governance for economics of $NEAR.
