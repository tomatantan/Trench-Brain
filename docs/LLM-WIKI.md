# LLM Wiki — 概念説明

> このドキュメントは「LLM Wiki」という概念そのものの説明である。特定の実装・題材には触れない。

## 1. 一言で

**LLM Wiki** とは、LLM が生ソースを読んで、構造化され相互リンクされた永続的な
マークダウンの知識ベース（wiki）を**少しずつ構築・維持し続ける**パターン。
合成（要約・分類・関連付け）は取り込み時に一度行われ、以後は維持される。
知識は時間とともに**複利で積み上がる**。

（Andrej Karpathy が提唱したパターンとして知られる。）

## 2. RAG との違い（なぜ存在するか）

- **RAG**: 質問が来る度に生データから関連チャンクを類似度検索して、その場で組み立てる。
  → 何も蓄積されない。5つの文書を跨ぐ微妙な問いには、毎回断片を集め直す。
- **LLM Wiki**: ソースを一度読んで知識を構造化ページに**合成して書き込む**。
  → 合成済み・相互参照済み・矛盾は整理済みの状態が残る。質問時はその合成を読むだけ。
  → ソースを足すほど、質問するほど、wiki が richになる（複利）。

要するに、RAG は「索引付けされた文書」を反映し、LLM Wiki は「**合成された知識**」を反映する。

## 3. 3層構造

| 層 | 役割 | 誰が触るか |
|---|---|---|
| **raw（生ソース）** | 不変の真実の源。記事・投稿・論文など。 | LLMは読むだけ・改変しない |
| **wiki** | LLMが全所有・維持するマークダウン群。 | LLMが書く・更新する |
| **schema（規約）** | wikiの構造・命名・ワークフローを定義する設定文書。 | 人が定義。LLMを"wiki管理者"に躾ける |

schema があることで、LLM は汎用チャットボットではなく「**wiki を維持する管理者**」として振る舞う。

## 4. ページ型

- **source summary（ソース要約）**: 1ソース1ページ。そのソースの要点・主張を蒸留。
- **entity（エンティティ）**: 人・組織・プロジェクトなど固有の対象ごとに**自動生成**され、
  新しいソースがそれに言及する度に**更新される**。事実の集約点。
- **concept（概念）**: アイデア・枠組み・パターンなど抽象。それを論じた全ソースを相互参照する。
- **comparison / synthesis**: ソース横断の比較や、質問への回答を資産化したページ。
- **index.md**: 全ページの目録。取り込みの度に更新され、埋め込み検索なしでページを探す入口。
- **log.md**: 取り込み・質問・点検の追記式の記録。

ページ同士は **`[[wikilink]]`** で相互リンクする。これがそのまま知識グラフになる。

## 5. 3つのワークフロー

### Ingest（取り込み）
新しいソースが入った時に走る。LLM はソースを読み、要約を書き、index を更新し、
**関連する複数ページ（entity / concept）に波及して更新**し、log に記録する。
1ソースの取り込みが複数ページの更新を引き起こすのが正常。

### Query（質問）
人が問いを投げる。LLM は index を見て関連ページを読み、**横断して合成し、
引用（wikilink）付きで答える**。価値ある回答はそのまま新しいページとして資産化する。
＝探索もソース取り込みと同じく蓄積する。

### Lint / Maintenance（点検・維持）
定期的に wiki を走査し、矛盾・陳腐化した記述・孤立ページ・欠けたリンク・
知識のギャップを検出する。

## 6. 中核となる原則

- **合成は一度きり、以後は維持**。質問の度に再導出しない。
- **矛盾は消さない。取り込み時に両論を併記して旗を立てる**（質問時に初めて気づくのではなく）。
- **entity は参照される度に更新される**＝知識が累積する。
- **クロスリファレンスを先に張る**ので、新ソースが入ると自動で関連既存ページが浮かび上がる。
- **書くのも読むのも LLM 向け**。wiki は LLM が後で読んで推論し、次の更新判断に使う「外部の記憶」。
- 人はソースをキュレーションし、戦略的な問いを投げる。**台帳付け（bookkeeping）は LLM がやる**。

## 7. メンタルモデル

- Obsidian（等のmdエディタ）＝ IDE
- LLM ＝ プログラマー
- wiki ＝ コードベース

知識を「書いて終わり」ではなく、リファクタし続けるコードのように、継続的に
整理・統合・再リンクし続ける。真の果実は個々の回答ではなく、
**文脈が複利で積み上がり、矛盾が自動で表面化し、任意の2つの情報の距離が縮まっていく
"生きた知識グラフ"が立ち上がること**にある。

## 8. どう成長するか

LLM Wiki は2つの入力で成長する。どちらも「外から来た入力」が起点であり、
LLM が独断でページを量産することではない。

1. **ソースが来る** → ingest → entity 更新・concept 創発（bottom-up）。
2. **問いが来る** → query → 横断回答 → ページ化（複利）。

維持（lint）は定期的に走らせる。これらが回り続ける限り、wiki は自律的に育つ。
