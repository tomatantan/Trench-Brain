# 芯チェック（CORE-CHECK）— 始める時と完了の節目に必ず回す

> 本人指示(2026-06-23): 「**始める時と作業完了の節目節目で、芯がブレてないかをチェック**」。
> 芯がブレる典型＝収集を増やす/新機能を足す時に、合成が追いつかず scraper 化する・門なしを足す・
> 自分や人の言葉で都合よく再フレームして原典から逸れる。これを始点と終点で機械的に潰す。

## 芯（the core）＝ LLM Wiki の実現
権威は **`docs/LLM-WIKI.md`（原典）**。本人の言葉でも自分の推論でもない。原典に照らして判断する。
1. **合成が収集に追いつく**（律速は合成スループット。原典§6/§8）＝`brain/state/health.jsonl` の **signal_backlog(§1a) が bounded/非増加**。これが「単なる収集(scraper)」でなく LLM Wiki である条件。
2. **収集は門付き**（curated・firehose 恒久禁止。指針2）。新ソースは必ず門(watchlist/canon/traction閾値)を通す。
3. **篩→合成**。合成は篩通過分だけ。**観測≠採用**＝raw総数で健康を測らない（増えるraw noiseは§4で事実集約され、深い合成は鮮度で優先）。
4. **両輪**（指針3）/ 両論⚠️（5）/ 観測と推論の分離（6）/ 全リンク・孤立なし（7）/ bottom-up・乱造しない（8）/ 淡々（9）。
5. **断定はデータが出てから**（早まった certify を反復した教訓）。

## ① 始める時チェック（着手前）
- [ ] これから足す/変える物は芯を壊さないか？ 一言で言える？
- [ ] 新ソース・新収集なら：**門付きか**／**合成が追いつくレートか**／**signal_backlog を構造的に増やさないか**（1ソースずつ・ペース制御）。
- [ ] 判断の根拠は **原典/指針か**（自分の都合の再フレーム・人の言葉の鵜呑みでないか）。
- [ ] 既存 concept/構造と突き合わせたか（矛盾するメモを書かない）。

## ② 完了の節目チェック（commit/報告前・データで）
- [ ] **signal_backlog(health.jsonl) は bounded/非増加か**。増えてたら＝収集過多のサイン→合成レートを上げる or 収集(option)を絞る。raw総数では判断しない。
- [ ] **持ち込んでないか**: 門なし収集 / raw放置(合成せず貯めるだけ) / concept乱造 / 観測と推論の混同 / 煽り・絵文字過多。
- [ ] 1ソースの取り込みが複数ページに波及したか（指針4）。孤立ページを作ってないか（指針7）。
- [ ] **原典/指針に照らして矛盾はないか**。断定する時は**データを示してから**。
- [ ] ブレを見つけたら：報告で正直に出す（隠さない）。直せるなら直す、設計判断なら本人に出す。

> 使い方: 着手時に①を、commit/報告の前に②を回す。チェックは形式でなく、**ブレを見つけて潰すため**。
